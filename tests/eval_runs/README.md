# Eval runs

* `2026-07-14_before_fixes/`: the first live run of `agent_eval_set.json` (13/24 passed) against the planner as it
  was before the date and comparison fixes. Kept as the baseline.
* `2026-10-08_after_fixes/`: live run after the fixes, 31/31 (the original 24 plus 7 new items). The summary lists
  what the live run caught that the offline tests had not, what the pass rate does not cover, and how the database
  was restored.
* `2026-10-08_heldout/`: a 29-question paraphrase set written after the fixes and run once unseen: 24/29. Its
  summary explains the five failures; after fixing them it is 29/29, which no longer counts as held out.
* `2026-10-09_heldout_v2/`: a second unseen paraphrase set (Canadian and Mexican places among them), written after
  the v1 fixes: 23/28 on its first run, 28/28 after fixes. Also the routing-confidence calibration check.
* `2026-10-08_answer_quality/`: are the LLM-written reports faithful to the data? 54/54 on four deterministic checks
  (Claude Sonnet), with what the checks miss. Run with `python tests/run_answer_quality_eval.py` (paid LLM calls).
* `2026-10-09_answer_quality/`: the same, after forbidding trend claims from samples (prompt and a new check):
  54/54 on five checks.
* `latest.json`: written by `python tests/run_agent_eval.py` (needs the backend, MySQL with the 2024 data and
  Ollama running). Not generated by CI.

The fast, offline checks (no Ollama, no database) are the pytest files in `tests/`; they run in CI. They include
`tests/test_eval_replay.py`, which replays all 88 eval questions through the planner on the router outputs recorded in
`tests/fixtures/router_cassette.json` (re-record with `python tests/record_router_cassette.py` after a router change).
Re-run the live set after any planner change and compare with the baselines above.
